# Deployment notes

Target: Vercel, domain `tarunlankireddy.com`. Nothing here has been run for you: publishing a repo, adding secrets
and pointing DNS are outward-facing, so each step is yours to do.

## 1. Before the first push

- [ ] `npm run test:site && npm run test:ask && npm run verify:chunks` pass.
- [ ] `git log --oneline` shows one initial commit (the old history, which contained a phone number, lives in
      `~/dev/portfolio-history-backup-2026-10-07/` and must never be pushed).
- [ ] `git ls-files | grep -E "^\.env"` shows only `.env.example`, and `git ls-files | grep ^internal/` shows nothing
      (`internal/` holds the build brief, design source, fact sheet and drafts, and is git-ignored).

## 2. GitHub

```bash
gh repo create tarunn31/portfolio --public --source . --remote origin --push
```

Then, in the repo under **Settings > Secrets and variables > Actions**, add the secret `ANTHROPIC_API_KEY`
(used only by the Ask eval workflow). The key is never written to a file or logged.

## 3. Vercel

1. Import the GitHub repo. Framework preset: Next.js. Node 20. Build and install commands: defaults.
2. Environment variables (Production and Preview):

| Variable | Required | Notes |
|---|---|---|
| `ANTHROPIC_API_KEY` | yes, for custom Ask questions | Server only. Without it Ask falls back to the email message and the site still works. |
| `NEXT_PUBLIC_SITE_URL` | yes | `https://tarunlankireddy.com` (metadata, sitemap, canonical URLs, Open Graph). |
| `NEXT_PUBLIC_REPO_URL` | optional | `https://github.com/tarunn31/portfolio`. When set, each Craft tile gets a "View source" link and the colophon links to the code. |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | strongly recommended | See the rate limiting note below. |

3. Set a monthly spend limit in the Anthropic Console.

### Rate limiting on Vercel

The in-memory limiter (5 per minute and 30 per day per IP) lives inside one serverless instance. On Vercel each
instance has its own counter, so the real limit is looser than it looks. Add Upstash Redis (Vercel Marketplace,
free tier) and set the two `UPSTASH_*` variables: the same limits then apply across every instance. The code
switches automatically and falls back to memory if Redis is unreachable.

## 4. Domain

1. Project > Settings > Domains: add `tarunlankireddy.com` and `www.tarunlankireddy.com`.
2. At the registrar (Porkbun), create exactly the DNS records Vercel shows for each (use those values, not values from memory).
3. Set `www` to redirect to the apex (Vercel offers this on the domain row).
4. Wait for the certificate, then open `https://tarunlankireddy.com`.

## 5. After the first deploy

- [ ] Link previews: paste the home page and each `/work/...` URL into a link preview checker (for example the
      LinkedIn Post Inspector). The cards are generated by `app/opengraph-image.tsx` and
      `app/work/[slug]/opengraph-image.tsx`.
- [ ] `/sitemap.xml`, `/robots.txt`, `/resume.pdf` (must be the phone-free version) and `/resume` (redirects).
- [ ] Ask: one suggested question (instant, no API call) and one custom question (calls the API).
- [ ] Lighthouse on the live URL, mobile.

## 6. Release routine

```bash
npm run test:site && npm run test:ask && npm run verify:chunks   # offline, free
npm run eval:ask          # live, a few cents: writes content/ask-eval.json
npm run build
npm run audit:lighthouse  # needs Chrome: writes content/lighthouse.json
npm run build             # again, so the colophon shows the numbers just measured
git add -A && git commit
```

The colophon and the "Tested against N prompts" line read those two JSON files at build time. Nothing in them is
typed by hand, and a line disappears until its measurement exists.

## 7. CI

- `ci.yml` runs typecheck, lint, the offline tests and a build on every push and pull request.
- `eval.yml` runs the live Ask eval only when `content/**`, `lib/ask/**` or the eval script change.
  It does **not** hold back a Vercel deploy: a push to the main branch deploys in parallel. A failing eval shows as
  a red check on the commit. To block deploys you would need required checks plus pull requests, or a Vercel deploy
  hook fired by the workflow, and that was left out on purpose.

## Known limits

- Lighthouse numbers are Lighthouse's simulated mobile profile on a production build served from the same machine.
  Real-world results on a CDN will differ, usually for the better.
- `npm audit` reports advisories in the dev-only ESLint tooling (not shipped). A normal `npm update` may clear them.
